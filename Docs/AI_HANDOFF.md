# Передача SERVERCLOSED другому ИИ

## С чего начать

Рабочий Unity-проект — **`Game1`**. Редактор **6000.6.5f1**, сцена
**`Game1/Assets/Scenes/ServerClosed.unity`**. Начальная точка — `ScBootstrap`.
Не заменяйте текущую сцену исторической `Bootstrap` или `SampleScene`.
Прочитайте корневой README, `CLAUDE.md`, отчёты
`Docs/Validation/2026-10-24-port-v1.1.md`,
`Docs/Validation/2026-10-25-soul-regions-v1.2.md` и
`Docs/Validation/2026-10-25-full-game-v1.3.md`.

Текущий статус: порт v1.3 — **полный перенос веб-прототипа**: v1.2 (душа, карма, суд,
регионы рождения, опасности регионов) плюс подземелья с боссами и приносами, задания
посёлка, сезоны с миграциями, полный посёлок с NPC/диалогами/набегами, Magic Chess,
«Чаша Отголосов» (открытие регионов ногами), тайная трещина, выбор тела при
реинкарнации и полный IMGUI-UI экранов. .NET-проверки 52/52 PASS (два прогона);
Unity-компиляция/EditMode/сборки для v1.3 — NOT RUN (выполняет автор, см. отчёт v1.3).
Не требуется заново переносить уже имеющиеся Core/Runtime из исходного архива.

## Что было исправлено

- Отсутствующие using и несовпадения типов в исходном C#-архиве.
- Пороги органов: отсутствующий множитель равен 1, а не 0.
- Новый Input System, E/Space, преобразование направления в изометрию,
  настоящий спринт и исключение кнопок HUD из движения по тапу.
- Карта открывается зрением; далёкие незамеченные существа не раскрываются.
- Вложенные списки разведки переживают JSON roundtrip, RNG и счётчик дней не сбрасываются.
- Ошибка загрузки не создаёт новую кампанию молча; есть проверяемый резервный слот.
- Реинкарнация сохраняет WorldData, карту, время и надземную популяцию.
- Тело слизня теперь действительно перемещает Transform к позиции игрока:
  раньше меш оставался в начале координат, отдельно от маяка.
- Исправлены повторное обновление первой точки контура и пути снимка на Android.

## Проверки перед продолжением

Сначала выполните EditMode-тесты `ServerClosed.Port.Tests` (теперь 52 кейса):
исторический результат v1.1 — `Docs/Validation/port-v1.1-evidence/editmode-results.xml`
(19/19 PASS), .NET-прогон v1.3 — `Docs/Validation/port-v1.3-evidence/dotnet-results.txt`
(52/52 PASS, два прогона); Unity-прогон v1.3 — за автором. После изменений отображения
проверяйте реальный кадр, а не только компиляцию.
У скрытого окна Windows ScreenCapture может возвращать чёрный backbuffer;
проверочный режим дополнительно рендерит камеру в RenderTexture.

Windows: `ServerClosed.exe --sc-smoke <папка-отчёта>` создаёт отдельные тестовые
сохранения и завершает процесс после проверки. Android Development APK поддерживает
boolean intent-extra `scSmoke=true`: результат пишется в
`Application.persistentDataPath/Validation`. В обычном запуске этот режим выключен.

В журнале Android есть сообщение движка о недоступном Java-классе
`com.google.android.play.core.assetpacks.AssetPackManager` до загрузки сцены.
Оно **не объявлено исправленным**. Сама игра, JSON под IL2CPP, HUD и повторный
запуск проверены на Samsung SM-G780F / Android 13. Также есть сообщения URP о Bloom.
Не добавляйте фиктивные Java-классы и не меняйте бинарные файлы Unity ради скрытия лога.

## Сохранения

`persistentDataPath/ServerClosedPort/sc_save_0.json` и `sc_save_1.json`:
версия 2, sequence, payload, SHA-256. Загружается самый новый валидный слот;
если он повреждён — предыдущий. Два плохих слота оставляются на диске с сообщением.
Перед сохранением состояния вызывается `ScWorld.CaptureState()`.
Формат веб-localStorage напрямую с C#-сохранениями не совместим.

задания посёлка, сезоны с миграциями, полный посёлок (NPC, диалоги, экономика,

(щедрость), набеги (оборона), предания Разлома (спросить Мирру о Разломе).

Из заведомо неперенесённого: визуальные слои веб-канваса (яркость светляков
`fireflyMul`, анимация смерти-растекания, палитры подземелий в изометрии — данные
уже в Core). Веб-реализация для справки — `Reference/WebPrototype/src/`. Это
источник для дальнейшего переноса, а не код, который должен компилироваться Unity.
Папки .env, node_modules, служебная Git-история чужого workspace и базы данных
из исходного TAR сюда не перенесены.

Не считайте v1.3 полным выполнением большой спецификации `Docs/Launch`.
Календарь: автор решил (25.10.2026) развивать 24-дневный год порта;
T-01 большой спецификации (120 дней) — историческое расхождение, не сводить молча.
Старые документы этапа M1 отражают историю, а не текущую готовность игрового порта.

## Правила работы

Сохраняйте .meta/GUID и фиксированные пакеты. Не коммитьте Library/Temp/Logs,
сейвы, ключи подписи, credentials или node_modules. Не меняйте старую отдельную
игру ServerClosed и не копируйте из неё материалы без запроса автора.
Пишите по-русски и различайте «скомпилировано», «тесты прошли», «APK собран»
и «запущено на устройстве». Для каждого изменения сохраняйте реальные результаты проверок.
