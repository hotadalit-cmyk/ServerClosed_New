# Тесты и критерии приёмки

Статус всех будущих игровых проверок в этом пакете: **НЕ ЗАПУСКАЛИСЬ**. Таблицы — задания и ожидаемые результаты, не отчёт о работающем коде.

## Методика

EditMode проверяет чистые правила и последовательности команд. PlayMode проверяет связывание UI, сцен, паузы и загрузки. Android проверяет IL2CPP, жизненный цикл процесса, файлы и реальные бюджеты. Моки допустимы для отказа диска и управляемой случайности; их успех не заменяет испытание файлов на устройстве.

Fixtures: seeds `1, 42, 20261023`; минимальный мир из двух регионов/поселений; нейтральный генотип (все аллели 0); bodyId `body-test-01`, soulId `soul-test-01`; фиксированная дата рождения. Генератор создаёт одинаковые ID и начальные ресурсы. Набор правил фиксируется хешем/версией.

## Сквозной сценарий E2E-01

1. Новая кампания seed 42; первый герой 18 лет, первый регион.
2. Обучение бою, 2 спутника, победа без смертельного риска.
3. Доставка пищи во второй регион за 2 дня; проверить даты обоих регионов.
4. Уникальное моральное решение, сохранение и перезапуск: изменение кармы одно.
5. Завершение проекта моста: изменился маршрут и хроника.
6. Через dev-сценарий перейти к пожилому телу без подмены общественных событий; отдельно проверить честное продвижение времени.
7. Завершить жизнь; зафиксировать SoulId, WorldId, M, местонахождение реликвии.
8. Reload итогов, выбрать происхождение; kill процесса посередине детства; продолжить.
9. Новому герою 18; прошло 18 лет; мост и хроника сохранились, старый инвентарь не скопирован.
10. Снова пройти бой и сохранить. Повторный reload не выдаёт награды второй раз.

Успех — все 10 шагов выполнены с наблюдаемыми состояниями, не только «экран открылся». Dev-ускорение отмечается в отчёте, обычный баланс оценивается отдельными кампаниями.

## Отчёт проверки

Для каждого прогона: дата, Git revision **нового** репозитория, Editor, rules/content versions, seed, platform, device, команда/шаги, ожидаемое, фактическое, PASS/FAIL/NOT RUN/BLOCKED, путь к XML/логу/скриншоту. «Тест написан» не равно PASS. Если аппаратной проверки нет, ставить NOT RUN и не закрывать M7.

Блокирующие дефекты: потеря сохранений; повторная выдача памяти/предметов; сброс мира при новой жизни; разные даты регионов; зависание перехода/боя; изменение старого проекта. Косметические дефекты допускаются только с описанным обходом, если не мешают чтению обязательной информации.
