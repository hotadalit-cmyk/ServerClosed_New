# Гены, RPG, магия и Magic Chess

## G. Упрощённая наследственность

**G-01.** Гены — свойства тела. Душа не передаёт свой генотип в другую семью. В первой версии один вид, шесть независимых локусов, по два аллеля на локус. Значение аллеля целое от −2 до +2. Это игровая модель, не научная модель наследования.

| Локус | Фенотип: среднее двух аллелей | Эффект |
|---|---|---|
| Constitution | −2…+2 | Максимальные HP ±10%: 5% за единицу |
| Power | −2…+2 | Физическая атака ±10% |
| Agility | −2…+2 | Инициатива ±10%; не шанс уклонения |
| Affinity | −2…+2 | Максимум маны ±10% |
| Endurance | −2…+2 | Максимум выносливости ±10% |
| Longevity | −2…+2 | Порог старения ±5 лет: 2.5 года за единицу |

Половинные значения фенотипа допустимы. Фракция, культура, карма, талант к добру/злу и приобретённые навыки не являются локусами.

**G-02.** Ребёнок получает случайно один из двух аллелей каждого родителя с вероятностью 50%. Для каждого из 12 переданных аллелей вероятность мутации 1%; при мутации равновероятно +1 или −1, затем ограничение −2…+2. Мутация на границе может не изменить значение. Seed = отдельный поток по `childId`, `conceptionEventId`, версии генетических правил. Порядок открытия экранов и количество визуальных эффектов не влияют на генотип.

**G-03.** Для именованных семей хранятся parentIds, genotypes и birthMinute. Для массовых жителей — частоты аллелей в когорте; при создании конкретной семьи значения выбираются из них один раз и сохраняются. Умерший родитель остаётся записью родословной. Безымянный предок не требует материализации всей генеалогии.

**G-04.** Близкородственные пары для генерации не используются: запрещены одинаковый ID, родитель–ребёнок, общие родители. Это проверка генератора, без сложной модели генетических заболеваний. При недостатке кандидатов создаётся новая семья мигрантов из нейтральной когорты; не зацикливаться в поиске.

**G-05.** Каждая стартовая комбинация играбельна. Даже все минимальные аллели не закрывают ни одну базовую специализацию. Исключено «улучшать расу» для доступа к главному содержимому. Предпочтительный билд можно получить навыками, снаряжением и тактикой. Частоты генов не вычисляются из моральных оценок цивилизации.

## P. RPG и характеристики

**P-01.** Герой уровня 1: сила 5, стойкость 5, ловкость 5, разум 5. За каждый новый уровень — 2 свободных очка, максимум уровня 20, максимум одной основной характеристики 30. Начальные значения происхождения используют перераспределение в пределах общего бюджета 20 и минимума 3, не добавляют скрытые очки.

`XPToNext(L) = 50 × L`, L=1…19. Для перехода с первого на 20-й уровень нужно 9500 опыта. На уровне 20 избыток XP не конвертируется в память души. Базовый обычный бой даёт 20 XP герою; важное задание 100; успешная месячная учёба 60. Баланс длительности жизни проверяется отдельно от скорости набора боевого опыта.

**P-02.** Базовые производные параметры героя до модификаторов:

| Параметр | Формула |
|---|---|
| HP | 100 + 20 × стойкость |
| Атака | 10 + 3 × сила |
| Броня | 2 × стойкость |
| Магическая сила | 10 + 3 × разум |
| Мана | 30 + 5 × разум |
| Выносливость | 50 + 5 × стойкость |
| Инициатива | 100 + 5 × ловкость |

Порядок расчёта: база характеристики → прибавки экипировки → генетический множитель соответствующего параметра → возраст → временные эффекты и синергии → ограничения → округление. Округление положительных боевых величин: половина вверх. Параметры хранятся в целых единицах или сотых долях; правила округления едины в Core. UI не вычисляет свои значения параллельно.

**P-03.** Навыки: оружие, защита, магия, разведка, ремесло, дипломатия, каждый 0–5. Цена следующего ранга `100 × (rank+1)` опыта навыка. За действие опыт получает только относящийся к нему навык. Один успешный бой: 10 опыта используемого боевого навыка, максимум один раз за battleId; месячная учёба: 100 соответствующему навыку. «Ученик» умножает этот опыт на 1.1, округление вниз. Навыки не начисляют уровни героя автоматически.

**P-04.** Снаряжение: оружие, броня, талисман, по одному экземпляру на слот. Каждый предмет имеет уникальный instanceId, владельца и тип. Перестановка разрешена вне боя и занимает 0 времени. Реликвии не дублируются при смерти/сохранении. В срезе 6 предметов: меч (+5 атаки), посох (+5 магической силы), кожаная броня (+5 брони), латная броня (+10 брони, −10 инициативы), оберег (+10 маны), походный набор (+10 выносливости).

**P-05.** Ранения: лёгкое (−10% maxHP на 3 дня), тяжёлое (−20% maxHP на 10 дней с лечением). Одинаковые ранения не складывают проценты, но продлевают срок до большего expiryMinute. Крайнее истощение относится к риску смерти из документа 02; оно не должно возникать от простого чтения меню.

## C. Тактический бой

**C-01.** Поле 6 столбцов × 8 строк. Команда игрока располагается на двух нижних рядах, враг на двух верхних; остальные — пространство манёвра. Отряд: герой плюс до 4 спутников. Резерв вне боя до 8; переход из резерва в бой после старта невозможен. Один живой юнит на клетку, недоступные клетки обозначены.

**C-02.** Фазы: `Setup → Running ↔ Paused → Resolving → Completed`. Подготовка без таймера. Все юниты, включая героя, действуют автоматически по выбранным приоритетам. Игрок может дать целевой приказ герою и активировать одно тактическое заклинание, если оно экипировано. Это выбранное правило новой игры, а не перенос управления из старой.

**C-03.** Фиксированный шаг 100 ms. Скорость x2 исполняет в два раза больше шагов на реальную секунду. Результат вычисляется только в Core. Один шаг: приём команд → истечение эффектов → выбор целей → резервирование перемещений → завершение движений → удары/умения → урон и лечение → смерти → проверка исхода. При равенстве приоритетов — stableEntityId по возрастанию. Одновременный взаимный смертельный урон разрешается в одном пакете, затем определяется ничья.

**C-04.** Базовый интервал атаки 10 тактов; `interval = max(3, roundHalfUp(10 × 100 / initiative))`. Первый удар после полного интервала, а не при создании. Один переход на соседнюю по стороне клетку занимает 5 тактов и 2 выносливости. При нулевой выносливости переход 10 тактов; стояние восстанавливает 1 за 10 тактов. Диагонали для движения отключены. Дальность — манхэттенская, препятствия блокируют линию огня.

**C-05.** Выбор целей: достижимая ближайшая → меньше текущих HP → меньший ID. Защитник держит ближний фронт; стрелок предпочитает дистанцию 3; целитель лечит союзника с наименьшей долей HP. Путь ищется на маленькой сетке, не чаще смены цели/блокировки. При конфликте резервирования выигрывает меньший ID; проигравший перепланирует на следующем такте. Нельзя проходить через занятые клетки.

**C-06.** Урон:

`damage = max(1, roundHalfUp(power × 100 / (100 + max(0, defence)) × positional × critical × abilityMultiplier))`.

Для физического удара power=атака, defence=броня; для магического power=магическая сила, defence=сопротивление (0 в базовом срезе, экипировка может добавить). Крит — 10%, множитель 1.5; случайного разброса 0.9…1.1 в v1 нет. Укрытие для дальнего удара множитель 0.75. Удар в спину 1.2, сбоку 1.0. Направление обновляется при выборе цели до пакета ударов. Бонус спины и укрытие перемножаются. Автоматического уклонения в v1 нет: меньше случайностей для первых тестов.

**C-07.** Магия: 4 заклинания с явными целями. Искра — 15 маны, 1.2 магической силы, дальность 3, cooldown 50 тактов; Щит — 20 маны, поглощение 30 на 50 тактов, cooldown 100; Лечение — 20 маны, восстановление 1.0 магической силы, cooldown 80; Корни — 25 маны, запрет движения 20 тактов, cooldown 120. Контроль не запрещает атаку в досягаемости. Повторные Корни обновляют expiry до большего срока, не складываются.

Недостаток маны/недопустимая цель: команда отклоняется без затрат и без cooldown. Щит расходуется раньше HP; лечение не поднимает умерших и не превышает maxHP. В бою +1 мана раз в 10 тактов до максимума. Вне боя полное восстановление требует отдыха; здоровье и мана не создаются повторным входом в бой.

**C-08.** Победа — нет боеспособных противников и есть хотя бы один союзник. Поражение — обратное. Если обе стороны пусты — ничья; если 1800 тактов без результата — отступление с исходом ничья, без награды за победу. Правила ранения/смерти героя описаны в D-01. Для среза обычные спутники при поражении ранены, не удаляются; именованные смертельные встречи могут иметь явно заявленные потери.

## MC. Шахматная подготовка и синергии

Термин Magic Chess — внутренний жанровый ориентир. Пользовательский интерфейс называет систему «Тактический строй». Чужие названия синергий, персонажи, ассеты и тексты не используются.

**MC-01.** Каждый юнит имеет ровно одну роль и одну школу. Роли: защитник, боец, стрелок, мистик. Школы: земля, ветер, пламя, поток. Синергия считается по **разным архетипам** в стартовой расстановке. Две копии одного архетипа не ускоряют пороги. Герой учитывается как отдельный архетип. Призванные временные существа не учитываются.

| Состав | Эффект на команду |
|---|---|
| 2 / 3 защитника | +10% / +15% брони, только старший достигнутый порог |
| 2 / 3 стрелка | +5% / +10% инициативы |
| 2 / 3 мистика | +10 / +20 maxMana и столько же стартовой маны, не выше maxMana |
| 2 / 3 школы земли | Щит 10 / 20 HP каждому в начале боя |
| 2 / 3 школы ветра | −1 / −2 такта перехода, минимум 3 |
| 2 / 3 школы пламени | +5% / +10% атаки и магической силы |
| 2 / 3 школы потока | +10% / +15% получаемого лечения |

Роль «боец» не имеет синергии v1; она компенсируется базовыми параметрами, UI это не скрывает. Синергии фиксируются при старте и не исчезают от смерти юнита: это сознательное упрощение. Бонусы одного типа из разных источников суммируются внутри категории, затем умножаются между категориями; выше +50% от синергий на один параметр не бывает.

**MC-02.** Армия кампании — реальные личности и контракты. Три человека не сливаются в одного. Улучшение качества юнита требует тренировки и ресурса, а не удаления NPC. В v1 нет звёзд, общего магазина и процентов на золото. Это сохраняет совместимость с генами и историей семей.

**MC-03.** Возможное расширение: отдельная учебная арена с иллюзорными фигурами. Только там допустимы 3 одинаковые фигуры → 1 улучшенная. У арены отдельный matchState, отдельное золото и фиксированные параметры без силы души/генов кампании; результат не меняет возраст тела и не выдаёт предметы кампании. Эта арена **не входит** в план M1–M7 и не должна незаметно стать вторым проектом.
