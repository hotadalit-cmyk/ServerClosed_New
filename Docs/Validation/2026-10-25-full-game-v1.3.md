# Валидация v1.3 — «Вся игра»: полный перенос веб-прототипа

Дата: 2026-10-25 · База: v1.2 (4d1d7e3) · Статус: **Core НАПИСАНО и СКОМПИЛИРОВАНО,
.NET-проверки 52/52 PASS (два прогона подряд)**. Unity-компиляция, EditMode-прогон,
сборки Windows/Android и реальный кадр — **NOT RUN** (Unity Editor 6000.6.5f1 в среде

## Сознательные отклонения от веба (продолжение списка v1.2)

1. **Суд применяется в момент смерти** (v1.2) — экраны суда/реинкарнации читают
   `JudgmentView()`; итог безопасен к перезагрузкам. Веб применял итог на кнопке.
2. **Календарь** — 24-дневный год порта (решение автора от 25.10.2026), T-01 (120 дней)
   остаётся историческим расхождением.
3. **Формула памяти души**: веб (`regions.ts`) считает «завершённые задания» по устаревшему
   списку id (wolves/hides/myco/shards/famine/titan); порт честно считает все 6 реальных
   заданий `quests.ts` (×1.5). Смысл формулы сохранён, дубль-ошибка веба не воспроизведена.
4. **Пути кармы** приведены к вебу (±40); прежние пороги порта ±25 удалены.
5. **fireflyMul (яркость светляков)** и анимация смерти-растекания (dyingT) — визуальные
   слои веб-канваса, в IMGUI-прототипе не воспроизведены; данные сезона (fireflyMul)
   перенесены. Реализация на ScIsoView — по желанию автора.
6. **Скорость боя**: мир в фазе шахмат остановлен кадром движка (как §7 «расстановка»);
   сам бой тикает по реальному времени 0.4 с — как в вебе (worldMinutesSpent += 3.3/тик).
7. **Восстановление популяции в DailyTick** использует веб-кривые (спирит 0.05 и т.д.)
   поверх стартового плана порта v1.1 (он чуть скромнее вебового; игрово-балансная разница
   в пределах уровня C §6). Осколышей (shardling) добавлено 2 в стартовый план — иначе
   задание «Хрустальные осколки» недостижимо.
8. **AdvanceDaysForTests** — публичный хелпер прокрутки дневных тиков для проверок/смоука
   (те же DailyTick(1), что при переходе дней кадрами); в обычной игре не вызывается.

## Совместимость сохранений

- Формат v2 сохранён (аддитивные поля): сейвы v1.1/v1.2 загружаются, `EnsureV13`
  (идемпотентно) достраивает NPC-тройку, словари флагов/атласа, стражу и военную силу
  посёлка, засеивает трещину; `wolfQuestDone`/`alphaKilled` согласованы с флагами.
- Новые обработчики ScJson: `List<Npc>`, `List<ChessUnitDef>`, `List<ChessUnit>`,
  `Dictionary<string,double>` (флаги), `Dictionary<string,int>` (worldRegions);
  `WorldData.chess` сериализуется посреди боя — набег переживает перезагрузку.
- `link.xml` сохраняет сборки целиком — новые модели покрыты автоматически.

## Что сделать автору (порядок)

1. `git am` патчи из `download/sc-v13-patches/` (или распаковать bundle поверх 4d1d7e3).
2. Unity 6000.6.5f1: открыть `Game1` → EditMode Test Runner `ServerClosed.Port.Tests`
   (ожидается 52 кейса) → проверить реальный кадр: посёлок, диалоги, вход в Катакомбы,
   бой с Монархом, Magic Chess (Дар при набеге), суд → выбор тела.
3. Сборки Windows и Android + `--sc-smoke`/`scSmoke=true` как раньше.
4. Если визуал подземелий в изометрии хочется детальнее — палитры из `dungeon.ts`
   перенести в `ScIsoView` (Core-данные уже готовы).

## Ограничения этой проверки

- Unity-компиляция (asmdef-ссылки, IL2CPP), EditMode, рендер, ввод — NOT RUN.
- Android AssetPackManager-лог — по прежнему решению не исправляется.
- Баланс набегов/шахмат в живой игре может потребовать подстройки кривой сложности
  (веб-формула перенесена 1:1).
