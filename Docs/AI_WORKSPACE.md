# Рабочее место GLM / ChatGPT / Unity

Статус: инструкция для настройки. Наличие ветки GitHub не означает, что Z.ai уже получил файловый доступ. Настройка ZCode на компьютере пользователя выполняется отдельно.

## 1. Одна кодовая база

- GitHub: https://github.com/hotadalit-cmyk/ServerClosed_New
- Проверенная точка старта: `84200bf1b77e95d5b37b974e45022e924cdabf01` (v1.3).
- Выделенная ветка настройки/работы агента: `agent/zai-workspace-v1`.
- Основная ветка `main` — проверенный код; объединение только после аудита.
- Unity Hub должен открывать `<папка-клона>/Game1`, но ZCode должен открывать `<папка-клона>` (корень Git).
- В репозитории нельзя хранить произвольные локальные сохранения, ключи подписи и сборочные кэши.

## 2. Как дать GLM реальный доступ к проекту (Windows)

1. Установить Git for Windows (если уже есть — использовать существующий Git).
2. Установить официальное приложение ZCode: https://zcode.z.ai/en/docs/install
3. Если репозиторий ещё не клонирован, выполнить в PowerShell (пример папки, путь можно выбрать другой):

   ```powershell
   git clone --branch agent/zai-workspace-v1 https://github.com/hotadalit-cmyk/ServerClosed_New.git C:\Dev\ServerClosed_New
   cd C:\Dev\ServerClosed_New
   git status --short --branch
   git rev-parse --short HEAD
   ```

   Если локальный репозиторий уже существует и содержит незакоммиченные изменения, НЕ клонировать поверх него и НЕ сбрасывать его. Сначала проверить `git status`. В такой ситуации можно сделать отдельный клон по другому пути.

4. Открыть ZCode. Войти через `Connect Z.ai` с тем аккаунтом, которому доступен GLM. Подключение модели зависит от тарифа/квот аккаунта.
5. В ZCode выбрать `Open Workspace` и указать корень клона `C:\Dev\ServerClosed_New` (не только `Game1`).
6. Попросить Agent выполнить лишь read-only проверку:

   ```text
   Открой текущую рабочую папку. Ничего не изменяй. Прочитай AGENTS.md, CLAUDE.md, README.md, Docs/AI_HANDOFF.md и отчёт валидации v1.3. Покажи путь проекта, git branch, HEAD, git status --short и список ключевых каталогов. Подтверди, что активный Unity-проект — Game1. НЕ запускай push или merge.
   ```

7. Открыть в Unity Hub именно `C:\Dev\ServerClosed_New\Game1` с Unity `6000.6.5f1` и проверить запуск сцены `Assets/Scenes/ServerClosed.unity`.
8. Каждую новую задачу начинать со сверки ветки, чистоты дерева, актуального ТЗ и тестов.

Если на компьютере уже установлены Unity/Git и репозиторий есть, повторная установка не нужна. Инструмент ZCode не требует самостоятельной сборки исходников самого ZCode.

## 3. Обычный чат z.ai/chat ≠ рабочая папка

Обычная переписка на https://z.ai/chat полезна для обсуждения и написания кода, но не имеет автоматически подтверждённых прав на локальный каталог/репозиторий. Настройка GitHub сама по себе этого не меняет.

Для непосредственного чтения, правки файлов, запуска тестов и Git используем ZCode Agent с открытым workspace. Старая история веб-чата не считается импортированной в ZCode. Автор может передать туда итоговый конспект/экспорт или добавить в `Docs/AI_CHAT_CONTEXT.md` подтверждённые решения.

Если принципиально продолжать только на сайте `z.ai/chat`, рабочий резервный вариант — обсуждать задачи там, передавать архивы/тексты и вручную переносить правки. Это не равнозначно прямому безопасному доступу к репозиторию.

## 4. Роли и типовой цикл

- Владелец: постановка целей, подтверждение направлений, приёмка релизов.
- ChatGPT: анализ требований, аудит кодовой базы и PR, проектирование ТЗ/критериев проверки.
- ZCode/GLM: внесение ограниченных изменений в рабочую ветку, запуск доступных тестов, подготовка диффов и отчётов.
- GitHub: единый источник версий, PR, обсуждения и протокол того, что действительно изменено.
- Unity: фактическая компиляция, тесты, сборка, проверка поведения.

Цикл: задача → инвентаризация файлов → план → небольшая правка → тесты → дифф → коммит в ветку → PR → обзор и корректировки → подтверждённый merge.

Для каждого нового этапа используйте отдельную ветку от актуального `main` после завершения текущего этапа; ветку настройки не превращать в бесконечную свалку.

## 5. Передача истории исходного веб-чата

В `Docs/AI_CHAT_CONTEXT.md` фиксируются только подтверждённые из чата или файлов:
- игровые требования и выбранные решения;
- запрещённые направления и ограничения;
- разработанные/неразработанные механики;
- открытые вопросы и расхождения;
- ближайшие задачи.

Записывать цитаты/ссылки на сообщения, если доступны. Без реального экспорта не выдавать реконструкцию по памяти за полный журнал.

## 6. Техническая валидация

- Минимум: `git status`, анализ диффа, проверка затронутого C# и существующих тестов.
- При наличии Unity: EditMode Test Runner, затем PlayMode/сценарии по характеру правок.
- Android: отдельная фактическая сборка ARM64/IL2CPP и тест на реальном устройстве для изменений ввода/UI/сохранений.
- Хранить результаты и ограничения в `Docs/Validation/`; не использовать неподтверждённые заявления «всё работает».

## 7. Работа с телефона

ZCode поддерживает Remote Control с телефона для уже открытого рабочего пространства. Компьютер, на котором выполняются команды, должен оставаться запущенным и доступным. Ссылку управления не публиковать: она предоставляет доступ к сессии. См. https://zcode.z.ai/en/docs/remote-control

Удалённая Linux/SSH-среда доступна в ZCode, но полный Unity Editor и проверка Windows/Android не появляются там автоматически. Для текущей игры проще начать с Windows-компьютера с Unity, затем при необходимости выделить отдельный сервер.
