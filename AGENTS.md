# Инструкции агенту разработки ServerClosed_New

Этот файл предназначен для ZCode / GLM и любых других агентов, которые открывают Git-корень репозитория.

## Обязательно прочитать перед изменениями

1. `CLAUDE.md` — основные правила автора и архитектурные инварианты.
2. `README.md` — актуальный Unity-проект, сборки и запуск.
3. `Docs/AI_HANDOFF.md` — устройство C#-порта и основные системы.
4. `Docs/Validation/2026-10-24-unity-v1.3-verified.md` — фактически зафиксированные проверки и ограничения.
5. `Docs/AI_WORKSPACE.md` — порядок совместной разработки.
6. `Docs/Launch/00_START_HERE.md` — спецификация и ссылки на документы игрового замысла.

Если источники противоречат друг другу, не придумывай решение: сопоставь исходники и журналы, зафиксируй расхождение, запроси решение автора, если без него не обойтись.

## Рабочая область

- Главный проект Unity: `Game1/`; версия редактора `6000.6.5f1`.
- Основной код: `Game1/Assets/ServerClosed/`.
- Начальная сцена: `Game1/Assets/Scenes/ServerClosed.unity`.
- `Game/`, `Game1/Assets/_Project/` и `Reference/WebPrototype/` — исторический каркас или справочные материалы. Не заменять ими рабочий порт.
- Этот новый игровой проект не переносит код, ассеты и сохранения из старого `C:\UnityProjects\ServerClosed`.

## Правила безопасности

- До изменений: показать текущую ветку, HEAD и `git status --short`.
- Работать в специально выделенной ветке; не менять `main` напрямую.
- Не использовать `git reset --hard`, `git clean -fdx`, force push и массовые удаления.
- Не трогать чужие незакоммиченные изменения; при них остановиться и описать ситуацию.
- Не удалять `.meta`, тесты, сцены, сохранения и конфигурацию пакетов без согласованной задачи.
- Не добавлять секреты, токены, ключи подписи, личные файлы, собранные APK и Unity `Library` в Git.
- Публикация, push, merge, релиз и запуск разрушающих операций требуют отдельного разрешения в соответствующем задании.
- Перед реализацией кратко назвать затрагиваемые файлы, план и риски; завершать работу проверяемыми небольшими коммитами.
- Сохранять требования из `CLAUDE.md`: Core — чистый C#, детерминизм, единое время, раздельные тело/душа/мир, версионированные и восстанавливаемые сохранения.

## Проверки и отчёт

Отличать просмотр кода, компиляцию, .NET-тесты, Unity EditMode/PlayMode, Windows build, Android build и испытание на устройстве. Для каждого этапа явно фиксировать PASS/FAIL/NOT RUN и реальные команды/логи. Не повторять исторические результаты как будто они только что получены.

В конце любой задачи сообщать:
1. что изменено, по каким путям;
2. почему изменено, связь с ТЗ;
3. какие тесты действительно выполнены и что не запускалось;
4. ошибки, известные ограничения и риски;
5. имя ветки, commit SHA и ссылку на PR, если опубликовано.

Не заявлять о прочтении всей переписки, если она недоступна.
